# Engine Support Matrix

This records behavior in the current runners. “Partial” means the feature has a known gap and must not be presented as a full guarantee.

| Engine | Resume after pause/restart | Expected checksum | Speed cap | Transfer quota | Authentication | Encrypted media | Live media |
| --- | --- | --- | --- | --- | --- | --- | --- |
| HTTP file and progressive media (`engine/task.ts`) | Conditional: byte journal and parallel ranges require a strong ETag at one final URL; sources without one restart in a single stream | Yes, before final rename (MD5, SHA-1, SHA-256 by digest length) | Yes, shared limiter | Yes, shared limiter for body bytes | Captured headers and HTTP challenge credentials scoped to origin | HTTPS transport; no DRM handling | No live-specific support |
| Separate video/audio URLs (`hls/dash.ts`) | Partial: both HTTP halves resume; finished halves can be reused, but reused output is not hashed | Yes, on muxed output before final rename | Yes, both halves share limiter | Yes, both halves share limiter | Same as HTTP for each half | HTTPS transport; no DRM handling | No live-specific support |
| HLS VOD (`hls/runner.ts`) | Partial: completed pieces reused when playlist identity matches; pieces are checked by existence/size, not digest | Yes, on muxed output before final rename | Yes, segment bodies use shared limiter | Partial: segment bodies counted; playlist/key/HTTP overhead is outside byte charge | Captured request headers; no HTTP challenge flow in runner | AES-128 segments supported; DRM is not | Rejected |
| MPEG-DASH MPD (`dash/runner.ts`) | No: ffmpeg pull restarts from zero | Yes, on ffmpeg output before final rename | Unsupported; task refuses an active cap | Unsupported; task refuses an active quota | Captured headers passed to ffmpeg; redirect and challenge behavior is not verified | Protected manifests rejected | Rejected |

**Finalization:** the manager can save requested captions and run the configured security scanner after transfer. Failure keeps the task actionable. Automatic restart of every post-processing stage and a fault matrix for each engine remain open.

**October 11 media repairs:** fragmented MP4 HLS joins its initialization header and fragments as one input per track; AES-128 initialization maps require an explicit IV. Streams that change initialization maps are rejected. Missing/corrupt playlist identity records invalidate retained pieces. HTTP conversion keeps the completed source in its workspace until the converted output succeeds, and media processes wait for output handles to close before cancellation returns. Torrent removal deletes metadata-listed payloads while preserving unrelated files and waits for seed teardown.

**Byte accounting:** a transfer quota is a limit on charged payload bytes, not a promise about all network traffic. Metadata, redirects, headers, retransmission, HLS keys, and tracker traffic need measured overhead bounds before any “network bytes” claim.

**HTTP validator policy:** a same-size file with no strong ETag is not safely resumable. A missing ETag on a ranged response triggers one clean single-stream retry; a changed ETag fails the task. A new final URL, including a refreshed signed media URL, invalidates the old journal even if the ETag text matches. An overlap-verified best-effort resume mode has not been implemented.

**Checkpoint and cancellation discipline:** HTTP checkpoints snapshot committed positions before syncing the payload; writes completed during that barrier remain pending for the next checkpoint. Positioned write batches never exceed the configured split margin. Composite video/audio pause waits for parent cleanup, and torrent pause waits for WebTorrent's piece-store teardown callback. HLS and MPD manifest requests follow the runner's abort signal; metadata-only torrent probes start deselected. Quota charges occur before a speed-limit wait so cancelling that wait cannot erase downloaded bytes.

**Resource bounds:** timeout-keyed HTTP pools retain at most eight cached dispatchers, retiring older pools after active requests finish. Shutdown destroys outstanding pools. Thumbnail loading runs at four concurrent jobs with a 32 MiB estimated retained-string budget and a 600-entry cap. These bounds do not constitute a bound on total Electron or WebTorrent memory.

**Range transport:** when a server supports ranges but supplies no strong ETag, a fresh download can request the entire known-size file as one range on one connection. This avoids plain-GET throttling on media CDNs without combining unvalidated responses or enabling partial resume. Compatibility mode still uses a plain GET.

**YouTube chunks:** fixed HTTPS Google media URLs whose signed parameters include object ID, format, revision (`lmt`), and the matching length (`clen`) use sequential requests of at most 10 MiB, even without an ETag. Every chunk must retain the exact URL and confirm the same total size. This provider-specific path relies on the signed resource identity; it does not enable parallelism, journal resume, or reuse across refreshed URLs. Large unbounded requests can be throttled by YouTube.

**Verification still needed:** changed content with identical size, expired live credentials, truncated reused media pieces, physical disk-full during mux, and power-loss recovery; a shared torrent throttle; task-owned DASH segment fetching; and installed-browser/live-provider journeys. Packaged isolated profile migration/restart, native-host handoff/replay, offline media-tool execution, and real fragmented-MP4/MPD fixtures passed the October 11 audit.
