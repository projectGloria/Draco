# Draco reliability audit — 11 October 2026

The review found and repaired failures in download integrity, media finalization, saved-state recovery, torrent deletion, command ordering, browser handoff, and renderer state. The final application passes **577 tests in 91 suites**, both TypeScript projects, production builds, Go bridge tests, packaged media-tool verification, packaged profile restoration, and packaged native handoff/replay.

This establishes tested behavior for the cases below. It does **not** establish that all possible bugs are gone. The remaining dependency advisories, engine limitations, and untested real-world conditions are listed explicitly.

## Scope and method

The review followed the authored main process, download engines, provider resolvers, preload/IPC contract, React renderer, Chromium extension, Firefox generation, Go native host, and packaging tools. It checked input admission through persistence, transfer, finalization, cancellation, deletion, restoration, and browser acknowledgements. Separate reviews covered desktop integration, media, and renderer behavior; the integration pass reviewed the changes and reproduced additional failures.

It is an inventory of the review scope, not execution or branch coverage. Generated Firefox copies were checked against their generator; third-party source, binaries, image/font assets, and generated bundles were not reviewed line by line.

Tests were run before changes: **509 passed**. Reproductions were added for observed failures, and relevant existing tests were retained. The final total is **577 passed, zero failed, zero skipped**. Several fixtures execute bundled production modules with only Electron/provisioning dependencies replaced; they do not replace the code being tested. Media fixtures invoke the actual bundled FFmpeg and FFprobe. HTTP fixtures use real local servers. Renderer callback fixtures exercise component hooks and IPC actions without mounting a graphical Electron window.

## Remaining limits and release confidence

The [engine support matrix](<C:/Users/Nihil/Desktop/Github Repos/Draco/docs/ENGINE_SUPPORT.md>) remains the capability contract:

- MPD delegates remote media fetching to FFmpeg. It restarts from zero and refuses active speed caps/quotas. FFmpeg's redirect/subresource credential behavior is not protected by Draco's per-hop HTTP guard. Task-owned MPD fetching remains an architectural gap.
- Torrent caps apply per client; simultaneous clients do not share a true aggregate app/queue throttle. Torrent quotas are deliberately refused. Live swarm/private-tracker/passkey behavior was not exercised here.
- Reused HLS pieces and completed separate video/audio halves are identified by playlist/format identity and existence/size, without per-piece persisted digests. Same-size local corruption may escape reuse checks unless an expected final checksum is supplied. The fragmented-MP4 repair does not solve that integrity limitation.
- HTTP journal resume requires the existing strong-validator policy. A fixed signed Google media object has a separate bounded sequential-range path; changing URLs cannot safely reuse unverified bytes. HLS live/DRM and changing initialization maps remain unsupported and explicitly fail.
- Private-host checks classify URL hostnames; DNS rebinding and FFmpeg-owned requests were not penetration-tested. The origin-scoping regressions establish the tested header boundaries, not a comprehensive SSRF guarantee.
- The packaged bridge smoke exercises real native frames and restart behavior, but it does not install/load the extension in a real Chrome/Firefox session. Authenticated live YouTube/X/Suno/KHInsider, provider changes, extension navigation/permission behavior, and a real torrent swarm still need end-to-end testing.
- Power loss, physical disk full/unplug, antivirus locking during every finalization stage, multi-hour sessions, and installer installation/uninstallation were not fault/soak-tested. Mocked disk failures and process cancellation do not replace those checks.

The audited local build is substantially better protected against the reproduced failures. Release confidence is supported by the retained tests and packaged checks; the unresolved items above must remain visible rather than being described as bug-free behavior.
