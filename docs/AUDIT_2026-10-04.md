# Downloader reliability audit — 4 October 2026

Reviewed HTTP transfers and resume journals, concurrency helpers, media runners, torrent startup and teardown, response handling, thumbnail memory, renderer startup, persistence, and browser bridge code. The checkout has no Git metadata; changes were made directly in the workspace.

## Fixed findings

| Area | Fault and resulting behavior |
| --- | --- |
| HTTP segmented writes | A network chunk could exceed the write-buffer limit and overwrite a tail handed to another worker during disk I/O. Writes now stay within the split margin. Abandoned response streams are cancelled immediately. |
| Resume checkpoints | A snapshot taken after `sync()` could claim writes outside that disk barrier. Snapshots now precede the barrier, and new bytes remain due for the next checkpoint. |
| Windows allocation | Opening a preallocated payload with `w+` discarded the reservation and valid data length. Existing allocated files now open with `r+`. |
| Concurrent work | `mapConcurrent` rejected while other workers were still touching files and starting more jobs. It now stops claiming jobs after the first failure and waits for active work before returning that error. |
| Transfer quota | Pausing during a rate-limit wait could skip quota accounting for bytes already written. The quota is charged before the wait. |
| HTTP pools | Each edited timeout could retain another pool indefinitely. The cache now uses an eight-entry LRU limit, gracefully retires old pools, and destroys outstanding requests at shutdown. |
| Media metadata | HLS playlist requests and MPD manifests now follow cancellation. HLS runner quality selection skips unnecessary rendition-size sampling. Failed or ignored HLS, crawler, thumbnail, and torrent-cache responses release their bodies. |
| Composite video/audio | Pause could return before parent mux cleanup, or child downloads could start after pause during finished-file adoption. Pause now waits for the lifecycle, and cancellation is checked after adoption. Checkpoint failures from sibling pauses are observed. |
| Torrent downloads | Default downloads started deselected and never selected any files after metadata. The metadata handler now selects all files when no subset is supplied. Client errors are observed before asynchronous descriptor lookup; that lookup follows cancellation. |
| Torrent removal | Pause returned before WebTorrent finished closing its piece store. Every pause now waits for its teardown callback before releasing the slot. Metadata-only probes remain deselected. |
| Thumbnail memory | An entry count alone allowed hundreds of large data URLs and simultaneous conversions. Retained strings now have a 32 MiB estimated budget, LRU eviction, and four concurrent loading jobs. |
| Renderer races | Initial snapshots could overwrite newer progress, and delayed progress-window reads could replace newer events. Startup merges pending progress; the progress window guards stale reads and unmounted effects. Speed history ignores progress for absent tasks. |

## Validation

- `npm test`: 509 tests passed, including new local HTTP fixtures and regressions for write ownership, checkpoint ordering, concurrency cleanup, quota accounting, pool retirement/shutdown, metadata cancellation, thumbnail eviction, torrent selection/teardown, and renderer startup.
- `npm run typecheck`: main and renderer projects passed.
- `npm run build`: production bundles and Firefox extension generation passed. Vite reports existing mixed static/dynamic import chunking warnings.
- `npm run host`: Go bridge tests and Windows bridge build passed.
- `npm run bench:http -- --output=tools/bench/results/http-audit.json`: all output hashes verified at 1, 2, 4, and 8 concurrent downloads. The eight-download case transferred 64 MiB of verified output at approximately 103 MiB/s, with about 143 MiB peak process RSS. This short local benchmark ran alongside other validation and is not a controlled before/after comparison or a long-duration leak test.

## Remaining verification and engine limits

Automated checks cannot establish that every bug is eliminated. Real authenticated providers, actual ffmpeg mux cancellation, disk-full failures, power-loss recovery, long sessions, and installer/browser journeys still need integration or soak testing. The composite cancellation fixture substitutes media provisioning and exercises the pause/adoption lifecycle without invoking ffmpeg.

The existing support matrix remains authoritative: MPD pulls cannot enforce a speed cap or quota; torrents apply limits per client without a shared aggregate throttle and refuse quotas; HLS completed-piece reuse checks existence/size rather than a digest. These capabilities have not been expanded in this audit. No new installer was packaged; rebuilt development bundles are in `out/`.
